# ch04 · 等待耗时与引用点击修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in this session. 后端执行 TDD；前端按用户要求直接实现并做浏览器验证，不套 brainstorm、TDD、code review。

**Goal:** 修复 8001 聊天页引用无法点击的问题，并通过逐阶段实测减少正常问题及无答案问题的等待时间。

**Architecture:** 保留现有 Milvus 原生混合检索、BGE 重排和生成自评链路。先建立当前服务耗时基线，再优化实测瓶颈；统一新旧证据字段，使当前回答和历史回答均能定位证据原文。

**Tech Stack:** FastAPI、SQLAlchemy、PyMilvus 2.6.17、Sentence Transformers 6.1.0、PyTorch 2.14.1、现有原生 HTML/JS 聊天页。

**Spec:** `docs/superpowers/specs/2026-10-05-sayhelp-ch04-hybrid-rag-design.md`，以及用户本轮“先给我修改计划，然后再进行修改”和“8001，每一次都比较慢，尤其是无法查询到匹配信息时更慢”的补充。

- dense 和 BM25 各召回 Top-50，Milvus hybrid_search + RRF，bge-reranker-v2-m3 精排 Top-10；不擅自改模型、召回数、阈值或推理后端。
- 保留元数据过滤、真实知识库、完整来源/索引一致性检查、useful 自评、引用验证、拒答及低置信度池约束。服务故障不能伪装成知识不足入池。
- 不加入指代消解、多轮改写；不缓存业务答案，不提前展示未经自评和引用验证的模型正文。
- 库/API 先查 Context7；额度不足时沿用已获授权的官方文档加本机版本/接口核验。
- 每阶段即时追记 dev-notes/ch04.md；保留已有用户改动，不提交 .env、密钥、虚拟环境和用户草稿。
- 完成并验证后提交并推送指定 GitHub；部署/验收针对用户实际使用的 8001 服务，核对其代码目录与进程。

## 诊断依据与取舍

1. 后端发 citations 事件，前端只接 sources；弹窗仍读旧版文件、摘要和行号字段，足以解释当前引用失效。
2. 本轮读取的历史校准12题中，检索中位数约5.57秒，重排约5.35秒；其中两道无答案题仍召回43条并重排约6.3秒。这不是当前端到端基线。
3. 现有生成器已在证据不足时跳过生成模型。无答案更慢需要核对问题理解、候选量和 CPU 重排，不能简单再加一个“低分拒答”或把 BM25 零命中当作无答案。
4. 推荐“测量后优化现有链路 + 修复证据协议”。只预热仅改善首次请求；只增加进度提示不能降低实际耗时；降低召回数或换模型违背既定选型，均不作为本轮方案。

## Review Focus

- 无答案、纯口语及具体型号问题：提速不能损伤召回或让错误问题入池（任务1、2）。
- 变更/丢失文档、缺失索引实体：保留明确故障，不能复用过期推理结果（任务2、3）。
- 非连续编号 [1]、[3]、[10]、越界编号及历史消息：编号按 n 映射，不能按数组下标猜测（任务3）。
- SSE 中断、服务超时及请求并发：不能展示未验证答案、串用计时或错误归因拒答（任务1、2、3）。
- 来源链接越界、文件摘要不符、移动端与键盘操作：只访问允许的同源文档路径，保留原始证据快照（任务3）。
