## 2026-10-04 — Task 3 review fix: settle persistence before releasing canceled turns

- **Reviewed defect:** Canceling an `asyncio.to_thread` await leaves its synchronous message insert running. The canceled stream could release its reservation and allow the next user row before the previous assistant row arrived, causing restart reconstruction to pair the old answer with the new question.
- **Changes:** Added one private message-write helper in `ChatService`. Each append runs as a shielded task; after cancellation the helper waits for the worker to settle, including repeated cancellation, then propagates `CancelledError`. All four append phases (user, tool request, tool result, final answer) use the helper. Read workers remain cancelable because they cannot append late rows.
- **TDD evidence:** Added `test_cancelled_persistence_settles_before_reservation_release_and_next_turn`, parameterized over four write phases and one/two cancellation requests. Focused RED: **8 failed, 18 deselected in 1.38s**, every case showing the turn exited while its database worker was still writing. After the fix, focused GREEN: **8 passed, 18 deselected in 1.23s**. Each test also runs a later turn and verifies saved row order plus correct completed-turn reconstruction.
- **Verification:** Covering chat/history suite with ignored `.env` loaded only into the process: **41 passed in 3.13s**. Full suite: **124 passed in 11.72s**, no skips or failures. `git diff --check` exited 0. The controller owns review and push.
- **Runtime effect:** Cancellation waits for the already-running database operation to finish before reservation release. This can delay disconnect cleanup by that operation's duration; it prevents late message writes from crossing a turn boundary. Existing tool-worker timeout uncertainty and no-write-retry behavior are unchanged.
