# 第六章浏览器验收（2026-10-12）

环境：本地单 worker `http://127.0.0.1:8096/`；真实 MySQL、Milvus、Jev 及既有聊天上游。模型请求计入 `eval/ch06/request-attempts.jsonl` 的 `browser-e2e`。截图留在忽略目录 `.runtime/ch06/browser-refund-receipt.jpg`，含真实订单细节，不推送公共仓库。

| 场景 | 实际观察 | 结论 |
|---|---|---|
| 无订单号问退款 | 提示客户 ID；回复已验证的客户 ID 后展示该客户订单商品卡片，没有猜订单号 | 通过 |
| 暂停及刷新 | 选单等待在刷新后仍存在；已消费旧卡片禁用，点选后出现“正在读取所选订单” | 通过 |
| 政策与表单 | 订单数据→查询扩写→政策来源→Agent 资格答复；eligible 才显示固定退款原因下拉；提交后只产生 pending 申请号 | 通过（另一次示例） |
| 表单刷新 | 已选原因和待处理申请号重新从服务端历史显示 | 通过 |
| 物流→退款→物流 | 第一轮真实物流正常；第二轮“这个能退吗”补全为明确商品和订单，Jev 判退款并展示选单；点选后政策弱证据触发显式兜底；第三轮“先不退了”恢复物流且未继续旧退款 | 分流通过，第二轮政策答复未通过 |
| 取消、重复点击 | 点选时卡片立即禁用；完成后卡片保持禁用。取消按钮有后端契约测试，但本轮没有完成独立浏览器取消操作 | 部分验证 |

独立意图验收 `intent-acceptance-r1.json` 为 101/110；独立政策验收 `policy-acceptance-r1.json` 为 21/24。这里不把浏览器的一条成功订单示例当成全场景通过。2026-10-13 环境重启后本地 MySQL/Docker 服务未启动，尚不能补跑浏览器取消场景；恢复服务后继续。
